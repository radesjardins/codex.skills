# Brainstorming Method Index

Read only the card for the selected method. Use one core method in a quick session. In a full session, add another method only when it is likely to produce a different underlying mechanism.

## Router

| Need | First method | Useful follow-up |
| --- | --- | --- |
| Frame an unclear problem | Starbursting | How Might We |
| Improve an existing idea | SCAMPER | Reverse Brainstorming |
| Find alternatives to a clear idea | Six Thinking Hats | Analogical Thinking |
| Find failure-driven opportunities | Reverse Brainstorming | How Might We |
| Break an industry pattern | Analogical Thinking | SCAMPER |
| Resolve a technical contradiction | TRIZ | Morphological Analysis |
| Lower perfectionism | Worst Possible Idea | Crazy 8s |

## Core generation methods

### SCAMPER

Use for an existing product, process, message, or idea.

Ask one lens at a time: Substitute, Combine, Adapt, Modify, Put to another use, Eliminate, or Reverse. Record each useful variation as a separate idea. Stop when another lens only repeats an existing mechanism.

### How Might We

Use to turn a clear observation into an open design question.

Form: `How might we help <primary user> achieve <result> within <hard constraint>?`

The question is ready when it permits several answers, states no solution, and stays within the session goal.

### Starbursting

Use when facts, users, or boundaries are unclear.

Generate the few questions that matter under Who, What, Where, When, Why, and How. Answer only the questions that could change the target or idea set. Convert the best open issue into a How Might We question.

### Reverse Brainstorming

Use when direct prompts produce familiar answers.

Ask how to cause the problem, make the experience worse, or guarantee failure. Convert each harmful mechanism into a prevention or opportunity. Keep the useful mechanism and discard the joke surface.

### Six Thinking Hats

Use when a clear idea needs several views without mixing them.

- White: facts and gaps
- Red: intuition and reaction
- Black: material risk
- Yellow: value and strengths
- Green: variations
- Blue: process and decision

Take one hat at a time. Keep Green separate from scoring.

### Analogical Thinking

Use when the current field keeps producing the same answer.

State the problem without field-specific terms. Find a field with the same function or constraint. Extract how that field handles it, then adapt the mechanism to the current goal. Reject surface comparisons that do not share a causal pattern.

## Optional named methods

### TRIZ

Use only for a clear technical contradiction, such as improving speed while reducing resource use. State the two conflicting properties, then try a small set of inventive principles: segmentation, extraction, prior action, inversion, adaptability, or self-service. Convert one useful principle into a specific concept.

Source: Genrich Altshuller, *The Innovation Algorithm*, Technical Innovation Center, 1999.

### Morphological Analysis

Use when a solution has three to five independent dimensions. List a few options for each dimension, combine one option from each row, and examine only combinations that meet the hard constraint.

### Crazy 8s

Use as a fast warm-up. Ask for eight short ideas before discussing them. Remove the timer when time pressure blocks the user.

### Random Entry

Use one unrelated noun to break a repeated pattern. List its traits, select one trait, and force a connection to the problem.

### Mind Map

Use to organize relationships around one topic. Preserve the source list. Offer Mermaid only when the links or branches are easier to understand visually.

### Worst Possible Idea

Use to lower perfectionism. Generate poor answers, name why each fails, then reverse one failure mechanism into a useful idea.

## Method rules

- Record ideas before judging them.
- Label each idea `[user]`, `[AI]`, or `[research]`.
- Change methods when the new output repeats the same mechanism.
- Keep exact or near duplicates visible until the user approves a merge.
- Move to `evaluation-frameworks.md` after generation closes.
